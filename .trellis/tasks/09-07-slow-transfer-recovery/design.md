# 技术设计

状态：方案已实现，默认启用策略已由用户确认；最终验证以 validation.md 为准。需求与验收以 [prd.md](./prd.md) 为准，来源见 [research/industry-and-code.md](./research/industry-and-code.md)。

## 1. 边界与交付顺序

一个任务内分三个依赖阶段：A 低速检测与受控恢复 → B 尾部接管 → C 有预算竞速。三个阶段共享请求状态、恢复预算、取消和所有权协议，完整验收后才宣告任务完成。C 不得偷偷从范围中删除；可默认关闭但必须能配置开启。

只处理已进入多连接 Range 路径的下载。单连接、不支持 Range、未知大小的现有行为不变。保持 max_connections 为原请求与备用请求合计的硬上限。

候选公开模式：`disabled`、`adaptive`、`adaptive_with_hedging`。用户已确认默认 adaptive，竞速显式开启。Rust 用策略类型和 builder，Python 使用统一命名解析并委托 Rust 默认；最终字段名在实现前接口复核中确定，单位为秒、字节、比例。

## 2. 请求观测与检测

每个活动 attempt 保存逻辑工作 ID、lease/generation、worker、范围、收到/转发字节、开始时间、最近非空数据时间和阶段。阶段至少分为 Headers、Reading、RateLimited、MemoryBlocked、ChannelBlocked、WriterBarrier、Backoff、Idle。

- monitor 定时驱动，绝不只依靠“收到下一个 chunk”触发检测。
- 原 read_timeout 继续负责等待头部/body 的无响应；低速窗口使用 Reading 的有效时间，不能计入本地暂停和背压。长时间本地阻塞后重建有效样本，避免陈旧低速窗口马上误杀。
- 速度采样分开保存“用于用户展示的端到端速率”与“用于诊断的有效读取速率”。收到空 frame 不算网络进展。
- 相对判定以同源、同下载的近期健康请求样本为参照，使用稳健统计；至少有两个合格参照样本才判定相对异常。保留最近已完成请求的有限样本，否则尾部只剩一个请求时失去基线。样本有期限，状态规模随并发和固定窗口变化，不随文件分片总数增长。
- 全部请求一起下降时暂停相对淘汰，优先记录整体瓶颈；仅凭历史峰值不触发循环重启。若显式配置绝对低速阈值，仍按有限恢复预算处理。
- soft 异常必须满足启动宽限、连续低速、预计可获益、冷却和预算条件；即将完成的请求继续等待。

压测候选参数（非行业统一值，需对照数据定稿）：1 秒采样、5 秒窗口、5 秒启动宽限、连续 15 秒低于健康基线 25%；绝对低速阈值默认不设置；恢复动作之间至少 10 秒冷却，同一 lineage 的自动性能恢复最多 2 次。

## 3. 预计完成时间和受控恢复

估算 `T_keep = remaining / current_rate`；对第一版整段重下估算 `T_replace = handshake_and_headers + full_segment_length / healthy_rate + cleanup/write_cost`。只有显著收益（候选 T_keep > 2 × T_replace，且预计节约 > 2 秒）才进行 soft 接管。近零速率、冷启动和过期基线有显式分支，不能用无穷值无条件触发。

硬网络错误继续走已有 RetryState。软性能恢复拥有有限次数、字节额度和冷却，不把正常慢网永久转成失败；额度用尽后保留仍有进展的当前请求，交由既有硬超时处理。已取消请求必须继续原逻辑工作的正常预算，不得重新领取后重置 max_retries/max_retry_elapsed。范围拆分后的子任务共享剩余 lineage 额度，不能复制额度放大重试。

对 429/503 保留 Retry-After；该源受退避约束期间不发性能恢复或竞速请求。自适应的“被其他 attempt 取代”是内部结果，不是任务 Failed，真实存储错误仍终止任务。

## 4. 尾部接管协议

调度状态区分：可领取、暂时无可领取但有活动/回收中工作、全部完成、不可恢复失败。空闲 worker 等待状态变化或任务停止，避免丢失唤醒和热循环；monitor 只检查活动 lease，不扫描全部 piece。

第一版采用整 segment 回收，再使用已有 min_segment_size 拆分器重新分配；不就地修改在途 HTTP Range，不保留未确认前缀。

1. 对目标 generation 标记 Recovering，停止新的竞速/分配，向该 attempt 发送局部取消。
2. worker 停止读取/转发并结束；取消必须穿透限速、内存、队列等待。monitor 不能仅 abort 后直接重新分配。
3. 等待 writer DiscardLease 的 FIFO ack，拒绝旧 generation 的所有后续 data/completion，回退该次未完成进度一次。
4. 回收逻辑范围，保留 lineage 预算；拆成不重叠子范围并唤醒空闲 worker。
5. 仅完整范围 flush ack 后记完成，所有子范围完成才设置 piece 完成位。

旧 attempt 与恢复发起同时完成时，采用锁内 generation 判定：已完成则恢复 no-op；已进入回收则旧完成不能再提交。不能让两条路径分别完成和 reclaim 同一个 lease。

## 5. 有预算竞速

触发条件：无普通待分配工作、有空闲并发槽、目标显著拖尾且已过延迟门槛、可验证对象身份、所有预算充足。不使用“下载到 90%”作为唯一条件。

- 每个逻辑范围最多主请求 + 一个 challenger；全任务同时最多一个 challenger；所有 HTTP 请求仍不超过 max_connections。
- 第一版只竞速一个完整的小 segment，上限 1 MiB。较大的 lease 先走整段回收/拆分；不增加部分 piece 持久化能力。
- 会话额外性能流量预算为 `min(文件总长 × 1%, 16 MiB)`，同时覆盖 soft 重下与竞速；小文件预算不够则跳过，不能偷偷向上取整。
- 在发请求前保守预留额度：竞速预留完整重复范围；soft 重下按整段长度预留。已发生流量不退还，未使用额度可在 attempt 结束后释放。预算是 Range body 工作量上界，不承诺限制内核/TLS 中已经在途的所有网络字节；记录实际应用层重复接收量。
- 基础网络错误的正常重试仍由已有策略限制，不把它们混作性能优化预算。

**写入隔离采用 challenger 临时文件暂存**：主请求保持唯一的主文件写入权；备用请求使用共享有界 chunk/内存预算流式写入临时文件，不能持有整个 segment 的 memory permits 等待获胜，否则小预算下会死锁。临时文件大小不超过备用范围上限，位置使用输出目录的唯一临时文件。

备用请求收完并通过范围、长度、对象 validator 校验后才有资格获胜。随后通过 generation 仲裁，停止旧主请求，等待旧 lease discard ack，再以新 authoritative lease 将暂存内容流式复制到主 writer、flush、完成。未完整暂存就不能撤销主请求，避免“收到头部很快，body 一直慢”的误切换。

主请求先完成则取消 challenger、删除暂存、不记失败；双方同时完成只能选出一个提交者。备用网络错误只结束该候选并计费，主请求继续。暂存创建/写入失败则跳过竞速并清理，主文件 writer 错误仍为任务致命错误。正常停止清理暂存；进程崩溃残留文件不参与 resume，清理只针对有明确本任务所有权的文件。

**对象身份**：竞速第一版要求探测取得强 ETag，主/备用 Range 均绑定同一 validator（拟用 If-Match），并验证响应；无可靠 validator、弱 ETag 或用户条件头冲突时禁用竞速且记录原因。缺少 validator 不应阻止原有普通下载。身份发生变化则失败并保留仅经过现有持久化确认的状态，不能拼接不同版本。此门槛属于最终技术规划，缺少强 ETag 的源仍可使用普通下载及受控恢复。

## 6. 进度、限速与连接

- downloaded/公开 speed/ETA 继续表达有效下载进展，不叠加 challenger 网络字节；胜者切换时按范围替换贡献，最终精确等于 total_size，不发生下溢或超过总长。回收允许沿用现有尝试失败的回退语义，不承诺进度严格单调。
- 单独诊断 wire_bytes、重复字节、恢复次数、当前阶段和抑制原因。所有副本网络读取均受同一个 max_download_speed 预算约束；从临时文件复制到主 writer 不再次消耗网络限速令牌。
- 共享内存预算只覆盖既有 queued/cached payload 及新增暂存流的有界 payload，明确不覆盖已有 HTTP/TLS 内部缓冲；正常和失败退出都回收 permits。
- 当前 HTTP/1.1 下，原响应仍在读时另一请求应使用其他连接；fixture 记录 TCP connection ID 验证。取消再发请求不能一概宣称“必定新连接”，需覆盖 pooling 开/关。第一版不实现自建连接池、强制换 IP 或周期性全池重建。

## 7. 兼容性、回滚与非目标

保持 control V1/V2 读写和 completed-bitset 权威性。恢复/竞速额外状态仅会话内保存；恢复下载可重新测量。公开 ProgressSnapshot 不必扩字段，先用结构化 tracing 避免无必要的 API 破坏。

模式 disabled 是完整回滚入口，应与当前行为等价。用户已确认 adaptive 默认启用、竞速显式开启。Python 所有入口同步配置、验证、异常映射及英文/中文文档。

不做 HTTP/2/3、镜像选择、代理切换、CDN 探测、生产集群访问、部分 piece 新持久化格式、无预算请求复制，也不保证共享源站限速场景获得加速。


## 8. 技术参数校准边界

采样/宽限/持续时间及 ETA 收益参数使用第 2、3 节列出的候选值开始基准校准；这是实现阶段的技术工作，不阻塞范围收敛。不得改变已确认的默认模式、扩大流量硬上限或放宽正确性验收。任何这种实质变化均需更新规划后评审。

## 实施校准

为满足 AC3，第一版在配置非零 max_download_speed 时保守地暂停所有性能恢复和竞速。显式限速与本地缓冲会改变可观察到的读取节奏，继续按读取时间推导绝对速率可能误判。仍保留分阶段等待诊断、普通错误重试及超时；未限速时的低速恢复和竞速行为不变。
