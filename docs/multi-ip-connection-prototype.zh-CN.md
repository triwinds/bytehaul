# 按 IP 分组连接池原型

日期：2026-09-12。对应 [实施计划](multi-ip-connection-plan.zh-CN.md) 的第一阶段。

## 当前结论

按 IP 分组的 Hyper HTTP/1.1 client 可以保留原始 URI、Host、TLS SNI 和证书域名验证，也能通过 `Connected::extra` 将真实远端地址、物理连接 ID 带到每次响应。复用同一 socket 时 ID 不变；不同 IP 的组使用不同 socket。

这一结论仅覆盖连接机制。原型位于 `src/network/multi_ip_prototype.rs`，使用 `cfg(test)` 隔离，尚未接入下载器、公共配置或 Python 绑定。候选选择、吞吐评分、收敛和公网对比均未实现，不能据此声称整个方案已完成。

## 已实现的可执行验证

- 两个不同回环 IP 分别建立组，交替执行正常 HTTP 请求，验证 Host、实际 peer、连接 ID 和池内复用。
- 信任本地测试证书，将 `origin.example` 定向连接到回环 IP，验证服务器看到原域名 SNI/Host；改用错误域名时 TLS 握手失败。
- 将请求名额放进响应体所有者，验证收到响应头后仍占用名额，读完或丢弃正文后释放，等待名额的请求超时不增加建连数。
- 用未完成响应体占住三个实际 socket，验证每组空闲上限 1 不代表并发上限 1。允许正文完成后验证只保留一个 socket，丢弃 client 后验证该 socket 也释放。
- 修复现有生产客户端缺少 `TokioTimer` 的问题，并验证客户端仍存活、没有下一次请求时，过期空闲 socket 也能回收。测试通过服务器收到 EOF 判断，不以本地请求计数代替真实连接状态。
- 验证中发现重试耗尽后提前回收租约存在被其他 worker 重新领取的窗口。通过 `SchedulerState::stop_and_reclaim` 原子停止新租约并清理失败租约；停止标记不写入恢复文件。新增调度器测试确保普通分配和指定子区间分配均被阻止，重新创建会话仍可恢复未完成数据。

## 生产接入需要遵守的边界

1. **三类预算分别维护。** 任务名额涵盖探测、数据请求、恢复及每一跳重定向；共享 origin 名额独立于单任务配置；全部 IP 组的空闲配额之和不得超过 origin 的空闲预算。原型仅验证显式请求名额及固定分组配额，尚未验证下载器全部调用路径。
2. **不要将请求名额当物理 socket 计数。** 原型分别记录 socket 创建/析构和响应体名额。实际 socket 关闭可能晚于响应体析构；Hyper 还会在池复用与新建连接竞争时让已开始的建连在后台完成。生产版本必须另行约束候选建连，不能只包一层响应体 semaphore 就声称物理预算成立。
3. **响应体必须包装。** 当前 `HttpResponse = Response<Incoming>`；仅在 response extensions 中保存租约会在 `into_body()` 时提前释放。生产版本需包装正文，并统一接入单连接、多连接和恢复路径。原型的 `finish()` 不是完整的统计入口。
4. **组容量和空闲配额必须统一管理。** 固定少量组的实验不能代替带 TTL、容量和淘汰的组管理器。避免给每个 IP 复制现有完整空闲配额。删除组时要考虑在途请求和 client 克隆延长旧池寿命。
5. **超时统一包住整个请求。** 包括 DNS、选择、预算等待、TCP/TLS 和响应头。候选切换不能重置期限；429/503 不能触发额外 IP 重试。
6. **代理保持原路径。** 原型不经过代理；连接归属和评分只能应用于直连源站。

暂时保留分组 Hyper client 作为候选架构，不开始重写连接池。第一阶段仍有任务级完整预算、后台建连竞争和动态组淘汰的验证待完成，因此不标记整个阶段验收通过，也不开放功能开关。
