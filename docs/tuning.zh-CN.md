# bytehaul 性能调优指南

本文介绍影响 bytehaul 下载性能和资源占用的关键参数。

[English Version](tuning.md)

## `piece_size`

**默认值：** 1 MiB  
**取值范围：** 必须大于 0

分片大小决定了多连接下载和断点续传的粒度。Worker 可以领取完整分片或同一分片的不同子区间；只有整个分片完成后，才能在控制文件中记录该分片的完成状态。

| 场景 | 建议值 |
|------|--------|
| 小文件（< 10 MB） | 256 KiB - 512 KiB |
| 中等文件（10 MB - 1 GB） | 1 MiB（默认） |
| 大文件（> 1 GB） | 4 MiB - 16 MiB |

**权衡点：**

- 分片更小：续传粒度更细，但调度开销更大，控制文件也会更大
- 分片更大：管理开销更低，但如果某个分片中途失败，恢复时可能需要重下更多数据

## `memory_budget`

**默认值：** 64 MiB  
**取值范围：** 必须大于 0

限制为 writer 队列和回写缓存预留的数据字节数。较大的响应数据块会先拆小，刷盘水位为后续块保留空间，因此预算很小或不能整除块大小时也能继续下载。极小预算会增加 channel 和磁盘 I/O 开销。HTTP/TLS 接收缓冲区以及其他进程内存不计入这个数据预算。

| 系统内存 | 建议预算 |
|----------|----------|
| ≤ 2 GB | 16 - 32 MiB |
| 4 - 8 GB | 64 MiB（默认） |
| ≥ 16 GB | 128 - 256 MiB |

**权衡点：**

- 预算更低：内存占用更少，但在慢盘上更容易因为等待 flush 导致 Worker 停顿
- 预算更高：快网络 + 慢磁盘场景下吞吐更平滑，但会占用更多内存

## `max_connections`

**默认值：** 4  
**取值范围：** 必须大于等于 1

单个下载任务可使用的并行 HTTP 连接数。Worker 可并发抓取不同分片，也可抓取同一分片中互不重叠的子区间。

| 网络 / 服务端类型 | 建议值 |
|--------------------|--------|
| 单台源站，家庭网络 | 2 - 4 |
| CDN 后端，高带宽链路 | 8 - 16 |
| 易限速或较脆弱的服务端 | 1 - 2 |

**权衡点：**

- 更多连接：总吞吐通常更高（直到触及网络或服务端极限），但会增加服务端压力
- 更少连接：对服务端更友好，失败时也更容易定位问题
- 许多服务端会按 IP 限制连接数；超过限制后可能出现 429 或连接重置

## `channel_buffer`

**默认值：** 64  
**取值范围：** 必须大于 0

HTTP 流读取层和回写缓存之间内部 Tokio channel 的缓冲区大小。它决定了网络层和缓存层之间最多允许多少个数据块处于 in-flight 状态。

大多数场景下默认值已经足够。只有通过性能分析确认 Worker 经常等待 channel 容量时，才考虑上调；当前日志不直接记录每次 channel 等待。

## `min_split_size`

**默认值：** 10 MiB

新下载中，小于或等于这个阈值的文件使用单连接，不受 `max_connections` 影响。这样可以避免小文件为了多连接协调而付出额外开销。

## `control_save_interval`

**默认值：** 5 秒

控制下载过程中检查 `.bytehaul` 控制文件保存条件的频率；实际持久化还受 `autosave_sync_every` 限制。检查更频繁可以缩小未保存进度的窗口，但也会增加 I/O。

| 场景 | 建议值 |
|------|--------|
| 高速网络，大文件 | 2 - 3 秒 |
| 慢速或按量计费网络 | 10 - 30 秒 |
| SSD 存储 | 3 - 5 秒（默认） |
| HDD 或网络存储 | 10 - 15 秒 |

## `autosave_sync_every`

**默认值：** 2

**取值范围：** 必须大于等于 1

存在尚未保存的进度时，每 N 次 autosave 检查执行一次 `sync_data + control save`。暂停、取消及网络失败会跳过这个批次限制，尝试保存断点；如果 writer 写入或同步失败，则保留此前的持久化断点，不会宣称新的进度已保存。增大该值能减少磁盘同步，但也扩大崩溃时丢失未保存进度的窗口。

## `max_download_speed`

**默认值：** 0（不限速）  
**单位：** 字节/秒

下载速率限制器。设置为非零值后，可以限制 bytehaul 占用的带宽，适合与其他应用共享链路时使用。

## 重试参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_retries` | 5 | 初次请求/传输失败后最多允许的额外重试次数（`0` 表示不重试） |
| `retry_base_delay` | 1 秒 | 初始退避延迟 |
| `retry_max_delay` | 30 秒 | 退避最大上限 |
| `max_retry_elapsed` | None | 总重试时间预算（`None` 表示不限时） |

请求和响应体重试共用指数退避，并叠加等抖动（equal jitter），以降低多个客户端下载同一服务端时同时重试造成的冲击。单连接 body 失败会从已 flush 的连续前缀续传；若 Range 或对象 metadata 不匹配，会安全地清空后从零开始。

## `request_batch_size`

**默认值：** 4 MiB
**单位：** 字节；设置为 `0` 可关闭合并

对已知大小的多连接下载，把相邻 piece 合并到一个有上限的 HTTP Range 请求中。它不改变
`piece_size`、检查点粒度和每个请求最多 64 个租约。需要保持严格的单 piece 请求边界时可设为
`0`；源站更适合小 Range 时可降低该值。增大它能减少请求和响应建立开销，但会减少其他 worker
可独立领取的工作，也可能放大单次请求失败后的重试成本。

## HTTP 空闲连接池

默认启用连接池：每个 host 最多保留 4 条空闲连接，空闲超时为 30 秒。源站不适合连接复用时，可使用 `DownloadSpec::disable_http_idle_pool()`，或将 `DownloaderBuilder::http_idle_pool(0, ...)` 作为显式关闭配置。服务端主动关闭连接时无法获得复用收益。

本地对比命令：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u http_proxy -u https_proxy -u all_proxy cargo run --release --example pool_compare -- 3 2
```

2026-09-06 的三轮交替测试使用 32 MiB 数据、4 个 worker、1 MiB piece，服务端对每次请求延迟 2 ms。关闭／开启连接池的中位耗时为 101.1／68.5 ms，接受的 TCP 连接数从 33 降到 5；每轮均为 33 次请求，输出逐字节一致。这是本机 HTTP 对比，没有覆盖公网、TLS 握手或代理可靠性；上线后仍应监控连接失败和源站行为。
