# 多 IP 建连与连接复用收敛计划

状态：实现中；第一阶段连接机制原型已落地，完整预算验收待完成。日期：2026-09-12。

相关调研：[其他下载器的多 IP、镜像选择与连接复用实现](multi-ip-downloader-research.zh-CN.md)。包含 aria2、curl、Axel 和 IDM 的源码/官方资料依据，以及对本计划的建议。

## 目标与约束

DNS 返回多个候选 IP 时，在正常下载需要建立连接的阶段，将连接分散到不同 IP；根据这些连接随后真实传输的表现，逐步优先复用速度快、稳定的少数 IP。

不增加独立测速请求，不专门下载测速分片，不修改分片划分算法。测速信息来自原本就需要执行的下载。仅建立 TCP/TLS 连接无法知道持续吞吐，尚未承载下载的连接只能积累建连信息，不能被判定为“下载最快”。

首版默认关闭，通过显式选项启用，验证后再决定是否调整默认值。当前落地测试原型，修复现有连接池空闲回收定时器和终止失败后的重试预算竞态，尚未接入多 IP 下载策略。

## 当前实现与实验依据

- `src/network.rs`：Hickory 解析并按 TTL 缓存候选地址；`lookup_host` 将地址迭代器交给 `HttpConnector`，没有下载性能排序。
- `BytehaulClient::Direct` 当前持有一个 Hyper legacy client；连接池通过 `pool_max_idle_per_host` 和 `pool_idle_timeout` 配置，没有项目自有的按 IP 选择连接逻辑。
- `src/http/worker.rs` 已有请求 ID、响应头耗时及响应扩展，可作为传输上下文的接入位置；请求 ID 不等于物理连接 ID。
- `src/session/single.rs`、`src/session/multi/adaptive.rs` 处理响应体与背压；后者已有慢速恢复机制。IP 选择需与这些机制协作，避免重复发起恢复动作。
- 公网 Citron ZIP 实验中，域名解析到的 IP 会变化，相同 IP 的不同轮次也有明显速度差异。因此使用近期表现、最小样本和迟滞，不能一次测量后永久锁定 IP。

实验记录位于本地 `target/public-compare/20260912-155135/analysis.zh-CN.md`。该目录不纳入版本控制，计划不依赖它才能实施。

## 预期行为

假设单个任务最多 8 个连接，当前 DNS 返回 3 个可用 IP：

1. 第一个连接立即尝试，不等待全部候选完成连接。
2. 后续正常并发请求需要连接时，优先选择尚未覆盖的候选，再按连接占用情况分配，初期尽量覆盖 3 个 IP。
3. 正常接收数据并记录各连接与 IP 的表现。样本不足时保持分散，不急于排除候选。
4. 样本足够后，后续请求和新连接主要使用前两个表现好的 IP；保留少量、受预算约束的候选尝试机会。
5. 慢连接上的在途请求正常完成；完成后不再优先复用。已有持续卡顿交给原慢速恢复逻辑处理。

“8”是任务预算，不是每个 IP 各 8 个连接。首版按正常请求需求建连，不额外预热一组空闲连接。若以后增加主动预热，预热连接和竞速中的连接必须显式占用连接预算，并有空闲回收机制。

## 架构选择

### 1. 域名候选与性能表

新增内部候选管理组件，按网络配置实例、scheme、host、port 隔离；每个 IP 记录：

- DNS 有效期、最近使用时间、失败冷却期限。
- 建连中、在途、可复用连接的数量或可验证的等价状态。
- TCP/TLS 建连耗时、请求响应头耗时、有效吞吐平滑值。
- 有效样本字节数、采样时长、样本数量和新鲜度。
- 连接失败、传输失败与非网络原因终止的分类计数。

性能历史设容量和过期限制，不持久化。DNS 到期重新解析；已移出候选集的 IP 不再接受新的任务分配，既有在途请求允许完成。网络切换后清理历史；若没有可靠的网络变化通知，至少提供客户端重建边界和短期历史过期机制，不声称能自动识别所有网络切换。

### 2. 可控制 IP 的连接复用

仅调整 DNS 地址顺序不够：已有域名连接池可能直接复用旧连接，绕过新的 IP 选择。

首选评估“按 origin + IP 分组的 Hyper client + 上层请求选择器”：

- 每个组的 connector 只连接选中的 IP；请求 URI 仍保留原域名。
- 上层为每个请求选择组，组内由 Hyper 完成 HTTP/1.1 连接复用。
- Host、TLS SNI、证书域名验证均使用原域名，不关闭证书验证。
- 每次重定向按新 origin 重新选择，不能继承上一跳的 IP 固定关系。
- 保持代理路径原行为。首版只处理直连 HTTP/HTTPS；不能将代理服务器的 IP 当作源站 IP 评分。

实施前必须用小型原型确认：实际远端地址/连接 ID 能可靠关联到响应；取消和丢弃响应体会释放占用；分组数量及总空闲连接有界。不能只在每个组复制原 `pool_max_idle_per_host`，否则总连接缓存会按 IP 数成倍增加。

Hyper 上层未必能直接获知准确的空闲连接状态，不能凭请求计数伪装成真实池状态。若该方案无法满足池预算或定向淘汰需求，再评估自有 HTTP/1.1 连接池；这是架构决策点，不在首版默认重写连接池。

### 3. 正常传输反馈

响应携带内部传输上下文，至少包含 origin、远端 IP、连接标识、请求 ID、候选代次。单连接、多连接及已有恢复请求均通过同一个统计入口反馈，避免重复计数。

吞吐统计必须包含等待远端数据的时间，不能只累计 body poll 实际执行的 CPU 时间。使用单调时钟记录传输观察窗口，并标记本地限速、内存预算等待、写入队列背压等区间；这些区间不应被直接归因为远端 IP 慢。首版优先丢弃受明显本地约束污染的窗口，避免过度扣除时间而高估带宽。

按连接/请求计算平滑速率，再聚合到 IP；不能按该 IP 的总字节数排名，否则分配到更多连接的 IP 会凭连接数量获得更高分。记录并发占用，区分单连接速度和节点在当前并发下的整体表现。

健康的完整传输窗口用于正常评分；取消、恢复挑战失败、正文未消费完、校验失败等只记录对应结果，不作为完整下载成功样本。连接租约持续到响应体完成或被丢弃，而不是收到响应头时就释放。

## 选择与收敛规则

首版采用可解释的规则，不引入复杂加权模型：

1. 过滤失效候选和仍在短期连接失败冷却中的候选；无健康候选时按现有重试预算做有界回退。
2. 未覆盖候选优先获得有限的初始机会；连接失败及时尝试其他候选，不等待所有候选失败后才返回。
3. 达到最小有效采样时长和字节数后，以近期有效吞吐为主排序；失败率用于降低优先级，建连和响应头耗时辅助决策。
4. 有多个稳定样本时主要使用前两个 IP；候选仅一个时自然退化为普通连接池。可用连接不足时不要为了等待首选 IP 空闲而饿死其他正常请求。
5. 使用明显差距阈值、最小驻留时间和低频重评，避免小波动反复切换。历史速率随时间衰减。
6. 非首选候选只有在正常请求需要连接、样本过期或首选退化时获得少量机会；探索不额外发出 HTTP 请求。

前两个 IP、最小样本、迟滞阈值和探索频率先作为内部策略参数，由受控实验确定数值；不一次暴露大量公共调参选项。池状态与评分锁不跨网络 await 持有。

连接失败可按 IP 短暂冷却；HTTP 429/503 不能简单当成某 IP 连通性失败。保留现有 Retry-After 和重试行为，不通过轮换 IP 扩大重试次数或规避服务端限流。慢速只影响后续分配，IP 选择器本身不新增在途请求抢占。

## 并发、超时与兼容性

- 将任务最大连接数、共享客户端的 origin 预算、IP 分组空闲缓存上限分别定义。多任务共享连接池时不能互相覆盖任务设置。
- 任务预算至少覆盖它触发的全部在途数据连接、恢复连接和候选建连；初始探测、重定向及透明重连的预算口径必须在原型阶段明确并测试。
- DNS、候选选择、池等待和建连仍处于现有每请求响应头期限内；不能每换一个 IP 就重新获得完整超时预算。
- connector 内部候选回退不增加应用层 HTTP 重试上限，也不重放已经消费的正文。
- IPv4/IPv6 均可成为候选，保留 `enable_ipv6` 行为及连接失败回退；首版不新增一套无预算的地址竞速。
- 关闭新策略时保持原路径。新配置若属于客户端级别，需进入 `ClientNetworkConfig` 的缓存键并传播到 Python 绑定；分组和成绩不得跨代理、TLS 或 DNS 配置复用。
- 不迁移正在持续下载的单个大请求。收敛效果主要体现在后续 Range 请求、后续下载及新连接；小文件可能在取得可靠样本前已经完成。

## 可观测性

结构化日志覆盖：候选列表和 TTL、实际远端 IP/连接 ID、选择原因、复用或新建、有效窗口字节/时长、受本地约束而弃用的样本、IP 排名变化、连接预算、冷却与淘汰原因。

完成时输出每 IP 汇总：连接数、请求数、成功/失败分类、有效字节、速率、占用峰值及切换次数。TRACE 提供细节，INFO 汇总；避免逐数据帧大量写日志。原始请求数与物理连接数必须分开。

## 实施步骤与验收

1. **连接复用原型**：验证按 IP 定向连接、原域名 TLS、远端 IP 归属、响应体生命周期及总预算。确定分组 Hyper client 是否满足要求，形成简短架构结论。
2. **候选分散与开关**：只实现初始分散、TTL 和失败回退，默认关闭。检查所有并发预算和原有超时语义。
3. **被动统计**：接入单连接与多连接的统一反馈，只记录不影响选择；用限速和背压场景确认不会误判。
4. **启用收敛**：加入排名、迟滞、低频探索及空闲淘汰；让已有慢速恢复保持唯一的在途恢复责任。
5. **受控验证与公网复测**：验证正确性和收益，记录开启/关闭差异，再决定是否默认启用。

受控测试至少覆盖：

- 多个地址分别提供快、慢和连接失败路径：初始有分散，稳定后后续请求多数进入快路径，候选失败不拖住全部任务。
- 中途交换快慢：旧成绩衰减，后续请求能重新收敛，切换次数受迟滞约束。
- 本地限速/写入背压：不把全部节点错误淘汰；样本不足不产生虚假排名。
- DNS TTL 更新、只有一个 IP、IPv6 禁用、重定向、代理、TLS 证书不匹配。
- 429/Retry-After、正文失败、取消、暂停恢复：无新增重试放大、无连接预算泄漏，文件一致性不变。
- 多任务共享客户端、响应体提前丢弃：占用和空闲缓存均有界。

吞吐算法测试使用可控时间和数据源，避免把不稳定公网速度作为 CI 断言。网络集成测试验证真实连接生命周期及 TLS；Rust 实现变更按项目要求执行相关测试和 Linux 95% 覆盖率门禁。

公网验证继续使用指定 Citron ZIP：先固定候选 IP 分别测量，再交替比较策略开启/关闭，固定连接数、文件、日志级别并重复运行。校验 SHA-256/ZIP CRC，记录每 IP 的连接占用和后续请求分布，同时报告失败率、中位耗时和慢尾，不能只展示最快一轮。若同一 IP 本身高度波动，报告策略收益的不确定性。

验收核心是：没有独立测速流量；连接预算不膨胀；真实数据归属和统计可信；受控环境能够收敛并适应变化；原有校验、超时、重试、取消、代理行为不回归。公网提速是实验结果，不预先承诺固定百分比。
